# Personas

## 1. Alex — programación (persona primaria técnica)

Trabaja en issues y pull requests a diario. Necesita saber qué PRs esperan revisión, qué CI ha fallado y qué dependencias bloquean su integración. Usa GitHub con fluidez; valora que HubForge no duplique Issues.

**Éxito:** abrir HubForge tras el fin de semana y retomar el hilo sin releer todo el repositorio.

## 2. Mar — arte / diseño (persona primaria no técnica)

Entrega assets y revisa impacto visual. No vive en la terminal. Necesita lenguaje claro: qué está bloqueado, qué se espera de ella y a qué issue o PR afecta.

**Éxito:** entender “este asset bloquea la integración de 3 trabajos” sin traducir jerga de CI.

## 3. Quim — producción / liderazgo indie

Coordina un equipo de 5–12 personas a tiempo parcial. Pregunta: ¿avanzamos?, ¿quién tiene capacidad esta semana?, ¿qué frena el hito?

**Éxito:** briefing + cola de atención como agenda de la siguiente sincronización corta.

## 4. Noa — guion / diseño narrativo

Trabaja en hitos creativos ligados a issues. Necesita ver dependencias y responsables, no un tablero Kanban genérico.

**Éxito:** saber si su entrega desbloquea a otros y si alguien puede revisarla.

## Anti-persona

Equipos enterprise que buscan sustituir Jira, o equipos que no usan GitHub como sistema de trabajo. HubForge no optimiza para ellos.
