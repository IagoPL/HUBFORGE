# Flujos principales

## 1. Onboarding (valor primero vía GitHub)

1. Iniciar sesión con GitHub.
2. Crear o seleccionar espacio (organización/proyecto).
3. Instalar GitHub App.
4. Seleccionar repositorio.
5. Importar / Sync now.
6. Configurar integrantes y roles funcionales.
7. Indicar disponibilidad semanal.
8. Abrir Briefing.

Crear tareas a mano no es el camino feliz del onboarding.

## 2. Regreso tras una ausencia

1. Abrir Briefing.
2. Leer hechos desde `lastVisitAt`.
3. Ir a Atención o actuar desde cada señal.
4. Abrir origen en GitHub cuando haga falta.
5. Ejecutar en Trabajo si corresponde.

## 3. Desbloquear trabajo

1. Abrir Dependencias o señal `work_blocked`.
2. Ver impacto (cuántos elementos frena).
3. Identificar responsable y acción.
4. Resolver en GitHub o en HubForge según el origen.
5. Confirmar que la cola reordena tras el desbloqueo.

## 4. Asignar con capacidad

1. Ver señal sin responsable o trabajo crítico.
2. Consultar capacidad del equipo.
3. Asignar a quien tiene hueco y rol funcional adecuado.
4. Mantener rol de acceso separado del funcional.

## 5. Modo demostración

1. Entrar a la demo sin conectar repo.
2. Recorrer Briefing, Atención, Trabajo, Dependencias y Capacidad.
3. Observar hechos vs inferencias etiquetados.
4. Conectar GitHub para abandonar la demo (datos reales distintos).
