# Arquitectura de información

## Navegación principal (objetivo)

1. **Briefing** — qué cambió desde la última visita y por qué importa.
2. **Atención** — cola operativa priorizada.
3. **Trabajo** — ejecución (lista prioritaria; Kanban secundario).
4. **Dependencias** — impacto de bloqueos y camino crítico aproximado.
5. **Equipo** — integrantes, roles funcionales y acceso a capacidad.
6. **GitHub** — conexión de repositorio, sync y estado de la App.
7. **Ajustes** — organizaciones, proyectos, preferencias, packaging.

Organizaciones y proyectos son infraestructura: accesibles desde Ajustes (y onboarding), no el centro del día a día.

## Superficies y trabajo

| Superficie         | Pregunta que responde                 |
| ------------------ | ------------------------------------- |
| Briefing           | ¿Qué debo saber al volver?            |
| Atención           | ¿Qué merece acción ahora?             |
| Trabajo            | ¿Cómo ejecuto o actualizo el trabajo? |
| Dependencias       | ¿Qué frena qué, y con qué impacto?    |
| Equipo / Capacidad | ¿Quién puede encargarse?              |
| GitHub             | ¿Está conectada la fuente de verdad?  |

## Jerarquía en Trabajo

1. Lista operativa priorizada (principal).
2. Tablero Kanban (secundario; no marketing).

## Chat

Fuera de la IA de producto del MVP. No aparece en rail, overflow, command palette ni landing.

## Modo demostración

Entrada visible sin repo real. Banner permanente “Modo demostración”. CTA para conectar GitHub y salir de la demo. Sin mezclar con datos live de Supabase.
